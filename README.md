# AcadMind — تطبيق Flutter متصل بـSupabase

هذه النسخة توسّع مشروع AcadMind الموجود وتحافظ على مسارات الدخول والضيف والمالك والمواد والمحتوى والمساعد الذكي. ارفع **محتويات هذا المجلد** إلى جذر مستودع GitHub بحيث يكون `pubspec.yaml` في الجذر.

## بناء APK عبر GitHub Actions

1. ارفع الملفات إلى فرع `main` أو `master`.
2. افتح GitHub → Actions → `Build AcadMind Flutter APK`.
3. عند نجاح المهمة نزّل artifact باسم `acadmind-universal-release`.

الـworkflow يهيئ Android runner، يولّد موارد أيقونة AcadMind بمقاسات Android، يشغّل اختبارات Flutter والتحليل، ثم يبني APK release. هذا البناء غير موقع بمفتاح Google Play؛ أضف keystore وSecrets عبر إعداد آمن قبل نشر إنتاجي، ولا ترفع keystore إلى المستودع.

## ما أُنجز في هذه الجولة

- الحفاظ على واجهات ووظائف المشروع الموجودة، بما فيها تسجيل الدخول/الضيف، الملف الشخصي، المواد والمحتوى، المساعد الذكي، لوحة المالك والتحديثات.
- سجل محادثات الذكاء الاصطناعي: استعادة محادثة، إعادة تسميتها، وحذف منطقي للسجل.
- مركز أكاديمي بتبويبات التقويم والأحداث والامتحانات والواجبات والتقدم والتدريب. المالك يستطيع إدارة الأحداث وتحديد نطاقها؛ والطالب يستطيع تسجيل إنجاز الواجب وجلسات المذاكرة.
- مؤشرات التقدم تُحسب من السجلات الموجودة بدلاً من عرض نسب افتراضية.
- اختبارات تفاعلية وبطاقات مراجعة: إدارة المالك للأسئلة والمجموعات ونشرها، حل الاختبار وتصحيحه على الخادم، ومراجعة البطاقات وحفظ حالة المراجعة.
- تذكيرات محلية للأحداث الأكاديمية إلى جانب تذكيرات الجدول الموجودة.
- أيقونة AcadMind إبداعية جديدة؛ ينشئ CI موارد launcher بمقاسات Android من `assets/branding/acadmind_icon.png`.
- ترحيلات الملاحظات والمركز الأكاديمي والاختبارات/البطاقات موجودة في `supabase/migrations/`، وطُبقت على مشروع AcadMind `skpjvgzxoholaapymvwd`. سياسات RLS تفصل المحتوى المنشور بحسب النطاق الأكاديمي، ولا تمنح الطالب قراءة الإجابة الصحيحة مباشرة؛ تسليم الاختبار يتم عبر RPC.
- تم تشغيل `flutter analyze --no-fatal-infos --no-fatal-warnings` بنجاح، واجتازت اختبارات الوحدة الثلاثة حسابات التقدم.

## ما يحتاج تجربة أو إعداداً قبل النشر

- لم يُنشأ APK داخل بيئة العمل: Flutter وDart متاحان، لكن Android SDK غير مثبت. بناء GitHub Actions لم يُشغّل من هذه النسخة ولم يُتحقق من artifact بعد؛ لا تعتبر APK مبنياً حتى تنجح المهمة على GitHub.
- يلزم اختبار تسجيل الدخول، الضيف، المالك، رفع الملفات، RAG، إدارة الاختبارات، والتذكيرات على حسابات وأجهزة فعلية. اختبارات الوحدة الحالية تغطي حساب مؤشرات التقدم فقط ولا تمثل اختبارات تكامل.
- الإشعارات تحتاج اختباراً على أجهزة فعلية، خصوصاً بعد إعادة تشغيل الهاتف وتغيير المنطقة الزمنية وإعدادات البطارية.
- خدمات الذكاء الاصطناعي ومعالجة الملفات تعتمد على Edge Functions الحالية ومفتاح `GEMINI_API_KEY` المحفوظ بأسرار Supabase؛ لا تضع المفتاح داخل Flutter أو المستودع.
- OTP عبر الهاتف يتطلب مزود SMS، وتأكيد/استعادة البريد يتطلب إعداد SMTP في Supabase.
- اختيار الإنجليزية غير مكتمل لكل النصوص والرسائل، والواجهة الثابتة ما زالت عربية في مواضع متعددة.
- تحديث التطبيق يفتح رابط APK؛ لا ينزّل التطبيق أو يثبته تلقائياً. Android يعرض التثبيت وفق إعدادات الجهاز.
- نطاق أحداث الدراسة ومحتوى الاختبارات/البطاقات يدعم الاستهداف الأكاديمي في قاعدة البيانات؛ اختبر إعدادات السنة والمجموعة والشعبة وملكية الحساب قبل استخدامه مع طلاب حقيقيين.

## إعداد المالك أول مرة

1. أنشئ حساباً عادياً من التطبيق.
2. افتح Supabase SQL Editor للمشروع `skpjvgzxoholaapymvwd`.
3. افتح `supabase/setup/promote_first_owner.sql`، واستبدل البريد الافتراضي ببريد الحساب الذي أنشأته، ثم نفّذ السكربت.
4. سجّل الخروج ثم الدخول من التطبيق. يجب أن تظهر تبويبة الإدارة.

لا تستخدم مشروع Supabase الخاص بسَكِينَة؛ AcadMind له مشروع مستقل.

## متطلبات التشغيل والأمان

- Flutter stable وAndroid SDK وJava 17 لبناء Android محلياً.
- ثبّت الحزم عبر `flutter pub get`.
- مفاتيح العميل في التطبيق يجب أن تقتصر على Supabase Publishable/Anon key. لا تضع `service_role` أو كلمة مرور قاعدة البيانات أو Gemini key في التطبيق.
- الترحيلات طُبقت على المشروع المذكور لهذه الجولة؛ راجع `list_migrations` وتأكد من البيئة قبل نشر أي نسخة أخرى.
- الأرشيف الأصلي لم يتضمن مجلد `android/` ولا `.git`؛ يُنشئ workflow مجلد Android أثناء CI. لذلك لا يوجد commit hash لهذه التغييرات.
